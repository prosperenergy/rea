# PROSPER Reverse Engineer

Use this skill to turn an app Craig identifies into a verified, usable PROSPER workflow. Establish the exact target, requested features, audience and deliverable from the conversation and live source. Inspect only access and data Craig is authorized to use. Do not treat a sample, a same-name identity match, or a missing record as verified fact.

1. **Observe the actual product.** Use a relevant connector before browser control where capable. For a website or app, inspect the actual user journey, menus, interactions, error states, mobile layout and data fields; preserve a concise evidence ledger with sources, dates, permissions, coverage and unknowns. Never claim a click, result or live data connection without evidence.
2. **Select the right tools.** For shipped artifacts, decompilation or behavior beyond available source, use the installed `reverse-engineer-anything` skill and available REA tools; inspect their current schemas. If unavailable, report the limit and continue with authorized methods. For an ordinary complete source repo use normal repository tools. Respect target-execution and credential boundaries.
3. **Translate into PROSPER.** Confirm which existing product, domain and data source own the feature. Avoid duplicates and preserve concurrent work. Recreate the requested user outcomes with original implementation; respect licenses and do not copy proprietary code or assets without rights. If branding is requested, use the currently applicable PROSPER theme and official assets; load the active theme skill and kit, not a guessed palette.
4. **Build the working flow.** Prioritize real mobile tasks, accessible controls, clearly labeled statuses, proper data attribution and durable saves. Clearly mark demos and synthetic data. Keep customer data and secrets protected; easy access does not imply publishing sensitive records or granting unverified users write access. Use individually scoped authorization appropriate to the actual instruction.
5. **Test and deliver.** Exercise the requested flows end to end, including mobile, persistence, empty/error states and access boundaries; use isolated data for write tests. Check the live owner, current deployment and concurrent changes before an authorized release. Verify the actual domain after publishing. Give Craig a clickable link and explain what works, what is sample-only and any blockers.

Do not invent leaderboard competitors or sales results. Do not send messages, spend money, change credentials, or bypass required authorization. Preserve Craig's instructions and applicable platform controls.
